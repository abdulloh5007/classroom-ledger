# Проверка перед открытой публикацией

**Дата:** 20 октября 2026 года

**Репозиторий:** [abdulloh5007/classroom-ledger](https://github.com/abdulloh5007/classroom-ledger)

**Публикуемая ветка:** `main`

## Что проверено

- Все коммиты, сообщения и сохранённые версии файлов, достижимые из публикуемой `main`, а не только последнее состояние исходников.
- Реальные удалённые ссылки GitHub: опубликована только `main`, других веток и тегов при проверке нет.
- Отслеживаемые и новые неигнорируемые файлы, документация и готовые frontend-ресурсы.
- Точные значения рабочих `BOT_TOKEN`, GitHub PAT и веб-пароля без вывода значений в отчёт.
- Характерные форматы токенов Telegram/GitHub, AWS/Google/Stripe и заголовков приватных ключей.
- Отсутствие `.env`, файлов SQLite и резервных копий в публикуемой истории.

**Результат:** совпадений с рабочими секретами и перечисленными форматами ключей в проверенной публикуемой истории, исходниках и сборке не найдено. Старый локальный архив истории не входит в опубликованные ссылки и не отправляется на GitHub. Публикация выполняется только для `main`.

## Что остаётся локальным

| Данные                           | Правило                                                                                                         |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Настоящие токены и пароль        | Секретные локальные настройки, права файла `600`; не Git и не frontend.                                         |
| `.env.example`                   | Только названия переменных, пустые секреты и примеры несекретных настроек.                                      |
| `data/app.db` и резервные копии  | Игнорируются Git; исходники и архив проекта их не содержат.                                                     |
| `OWNER_ID`, имя автора, имя бота | Публичные идентификаторы, а не ключи доступа. Telegram ID сам по себе не позволяет выдать себя за пользователя. |
| Пароли в тестовых сценариях      | Фиктивные значения для изолированных проверок; рабочий пароль в тестах не используется.                         |

## Границы результата

Это проверка репозитория по известным рабочим значениям и набору сигнатур, а не гарантия обнаружения любого возможного секрета. Она не отзывает ранее переданные через чат токены и не проверяет их использование в других проектах. При компрометации токен нужно перевыпустить у его провайдера.

Открытый GitHub публикует исходники и их проверенную историю. Он не отключает вход в приложение, не предоставляет сессию к API и не меняет права Telegram-пользователей. Рабочие данные при публикации не удаляются и не загружаются в репозиторий.
