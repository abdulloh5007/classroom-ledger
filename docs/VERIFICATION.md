# Фактическая проверка

Проверено 19 октября 2026 года в этой рабочей среде, Node.js 24.22.0.

- `npm install` — успешно; версии закреплены в package.json и package-lock.json.
- `npm run typecheck`, `npm run lint`, `npm test` — успешно, **46 тестов в 5 файлах**.
- `npm run build` и `npm start` — production-сервер раздаёт HTML, CSS, JS, локальные шрифты и JSON API.
- `npm run dev` — API, Vite, HMR и Telegram polling работают на одном порту. Для данного экземпляра выбран **127.0.0.1:3107**, чужие процессы не останавливались.
- Telegram `getMe` успешен, бот **@corpibotbot**, long polling запущен. Поддержка поля `style` сверена с официальными документами и установленными типами grammY 1.46.0. Владелец должен отправить `/start`, если Telegram ещё не знает его личный чат и не принимает chat scope меню.
- Проверки реальных HTTP-запросов: `/` → 200, `/health` → 200, CRUD и ошибки API дополнительно проверяются Fastify.inject.
- Chromium / Playwright: создание и редактирование ученика, Radix Select, внесение оплаты, изменение долга, история оплат, поиск, следующий/предыдущий месяц, переключение темы, подтверждение удаления и каскадная очистка прошли.
- Проверены мобильные размеры 390×844 и 360×780, а также desktop 1280×900; горизонтального переполнения нет.
- Axe WCAG 2 A/AA, WCAG 2.1 AA: на экране должников в светлой теме, учеников в тёмной теме и открытой форме оплаты не найдено нарушений. Первичная проверка выявила недостаточный контраст мелкого текста; CSS исправлен и проверка повторена.
- Проверены валидация пустой формы, возврат фокуса на открывшую кнопку после Escape и закрытие sheet перетаскиванием вниз с включёнными анимациями.
- Ошибок выполнения JavaScript в проверенном полном браузерном сценарии не было.
- `npm audit` — 0 известных уязвимостей на момент установки и проверки.
- Токен хранится только в `.env` с правами 600. `.env`, SQLite, зависимости и сборка исключены из Git и архива исходников. Тестовые ученики удаляются по ID, полученным при создании; пользовательские записи не изменяются.

Браузерные проверки запускались из изолированного каталога `/tmp`: это не добавляет Chromium и Playwright в обязательные зависимости приложения. Недостающие библиотеки Chromium распакованы в `/tmp`, системные пакеты не изменялись.

## Что ещё требует человека

Нужен проход в реальном Telegram-клиенте под аккаунтами владельца, администратора и постороннего пользователя. Обработчики проверены mock-транспортом, но автоматическая проверка не заменяет выбор контакта через request_users, пересылку от пользователя с закрытой приватностью и отображение цветов на разных клиентах Telegram. Safari/iPhone, экранный диктор и жест пальцем на устройстве не проверялись; Chromium проверяет только часть браузерной совместимости.

Скриншоты в `docs/screenshots` содержат временные тестовые записи, а не реальные персональные данные.

## Обновление интерфейса и внешний доступ

Карточки скруглены на 28–32 px, поля — на 20 px, кнопки и переключатели — капсульные, sheet — 36 px. После изменения повторно пройдены локальные браузерные CRUD-сценарии и axe в светлой/тёмной темах.

`/start` и `/help` доступны гостю: приветствие, имя, роль и Telegram ID в HTML `<code>`. Гостевой доступ не выдаёт прав на финансовые команды. Для этих случаев добавлены тесты, включая экранирование имени.

Актуальная версия использует страницу `/login` и cookie-сессии вместо первоначального Basic Auth. Через внешний HTTPS проверены `/login` (200) и отказ без сессии для `/students` (401). Авторизованная проверка через внешний tunnel не выполнялась: автоматическая проверка отклонила передачу учётных данных внешнему сервису. Локальный авторизованный браузерный проход успешен.

Node.js и отдельный Cloudflare Tunnel запущены как пользовательские сервисы `ecomdev-ledger` и `ecomdev-ledger-tunnel`. У других проектов процессы и порты не менялись. Подробнее: [DEPLOYMENT.md](DEPLOYMENT.md).

## Страница входа

Добавлены форма входа, ошибки пустых полей и неверного пароля, показ/скрытие пароля, loading, переключение темы и кнопка выхода. Сессия хранится в SQLite и HttpOnly cookie, истекает через 12 часов, отзывается при выходе и смене пароля. Тесты проверяют вход, отказ без сессии, Secure для HTTPS, поддельный и просроченный cookie, сохранение после перезапуска и ограничение попыток. Локальный браузерный проход отдельно проверяет интерфейс формы, вход, обновление страницы, выход, светлую/тёмную темы и мобильную ширину.

Браузерная проверка новой формы завершена успешно: пустые поля, неверный пароль, показ/скрытие, успешный вход через локальный адрес, HttpOnly cookie, обновление страницы с сохранением входа, выход с удалением cookie и 401 для API. Axe не обнаружил нарушений в светлой и тёмной теме; на 360 px нет горизонтального скролла. По публичному Cloudflare-адресу отдельно проверена отрисовка формы и загрузка её ресурсов без ввода или отправки учётных данных.

## Переработка оформления по пользовательскому референсу

Через предоставленный доступ прочитаны frontend-файлы референса: `ios.css`, `controls.css`, `select.js` и `navigation.js`. Перенесён общий подход: системная типографика, компактные поверхности, аккуратные поля, синий акцент, пружинный индикатор вкладок и плавный Select. Убраны оба футера, слоганы и декоративный фон входа. Приватные исходники референса и GitHub PAT в этот репозиторий не включены.

Для native date применены ограничения intrinsic-width: `min-width:0`, `min-inline-size:0`, `max-inline-size:100%`, `appearance:none` и `minmax(0,1fr)` у сетки. Все три поля формы оплаты имеют одинаковые размеры. Живые измерения Chromium:

## Предзагрузка истории, монохромная тема и защита

В последнем проходе использовался отдельный production-сервер со случайным портом и in-memory БД; реальная база не подключалась. Chromium проверил:

- Запрос первой страницы завершился до открытия истории; открытие из кеша не вызвало повторного запроса.
- 25 оплат показаны порциями 10/10/5; общая сумма сразу относится ко всей истории.
- Ошибка сети при следующей странице сохранила показанные записи, после восстановления сети повтор успешно загрузил остаток.
- После оплаты кеш сброшен: история показала 26 записей и обновлённую общую сумму.
- В будущем месяце появляется «План на месяц»; возврат к текущему возвращает пояснение об отдельном расчёте каждого месяца.
- HTML в имени показан как текст, обработчик onerror не исполнился. Production CSP не разрешает inline JS; файлы шрифтов вынесены из data-URL.
- Пути `.env`, `.git/config`, `data/app.db`, `src/config.ts` возвращают 404 через production static.
- На 360/390/428/720/1280 px дата, сумма и Select одинаковой ширины; горизонтального переполнения нет.
- Светлая и тёмная темы имеют монохромные primary/accent. Скриншоты `monochrome-light.png` и `monochrome-dark.png` содержат только синтетические записи.
- Viewport запрещает масштабирование; отменяются gesturestart и многопальцевый touchmove, обычный однопальцевый скролл не отменяется. Это проверка обработчиков, не фактического жеста на iPhone.
- В axe осталось ожидаемое нарушение `meta-viewport`, вызванное явным требованием запретить масштабирование. Других нарушений WCAG 2 A/AA, 2.1 AA в проверенных состояниях формы оплаты и обеих тем не найдено.
