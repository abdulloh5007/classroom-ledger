# Класс · Мини-учёт оплат учебного центра

Автор: **Abdulloh Ergashev** · Выпуск **1.3.0**.

Node.js + TypeScript strict, Fastify, Zod, SQLite / better-sqlite3, grammY, React / Vite, Radix UI и Framer Motion. Один `package.json`, один сервер и один origin. API и Telegram-бот вызывают общий сервис `LedgerService`; бот не обращается к API по HTTP.

## Запуск с нуля

Нужен Node.js **20.19+** (рекомендуется актуальный LTS 22/24) и npm. Если для вашей платформы нет готового better-sqlite3, потребуются Python 3 и компилятор C/C++ (`build-essential` в Debian/Ubuntu, Xcode Command Line Tools в macOS).

Клонируйте приватный репозиторий под GitHub-аккаунтом с доступом:

```bash
git clone https://github.com/abdulloh5007/classroom-ledger.git ecomdev-ledger
cd ecomdev-ledger
npm install
cp .env.example .env
```

В `.env` заполните `BOT_TOKEN`, полученный у BotFather, и свой `OWNER_ID`. Числовой ID владельца в примере — `5320242541`. Секреты читаются исключительно из `.env`. Этот файл исключён из Git и не попадает во frontend-сборку. Без токена веб и API работают, Telegram-бот отключён.

```bash
npm run dev
```

Откройте адрес, напечатанный сервером: по умолчанию **http://127.0.0.1:3000**. Если порт занят, сервер ищет свободный в диапазоне `PORT…PORT+50`, не завершая чужие процессы. API, Vite HMR и бот работают совместно; отдельный порт Vite не нужен. Для изолированного запуска этого экземпляра в локальном `.env` выбран `PORT=3107`.

Веб изначально пустой. Сначала создайте группу, выбрав курс или добавив его круглой кнопкой «+», затем добавьте ученика во вкладке «Ученики». По желанию можно загрузить четыре явно демонстрационные записи:

```bash
npm run seed
```

Seed работает только в пустой базе и не изменяет существующих учеников. Дата демо-платежей — текущая. Seed не выполняется автоматически при старте.

Production (предварительно остановите свой dev-процесс через Ctrl+C, особенно если используется тот же бот):

```bash
npm run build
npm start
```

Fastify раздаёт готовый `dist/web`, а также API. В production Vite не запускается. Сервер слушает только loopback `127.0.0.1`, поэтому соседние проекты и внешняя сеть не затрагиваются. На другом компьютере/телефоне для доступа потребуется ваш reverse proxy или SSH-туннель.

```bash
npm test
npm run typecheck
npm run lint
npm run format:check
```

`package-lock.json` включён для воспроизводимости; вместо `npm install` при последующих установках можно использовать `npm ci`. БД `data/app.db` создаётся при старте. Миграция в транзакции отмечается через `PRAGMA user_version`; включены FK, WAL и индекс `(student_id, paid_at)`. Остановить приложение — Ctrl+C: polling, Vite и БД закрываются корректно.

## API

Все суммы в SQLite и API — **целые минимальные единицы** от 1 до 1 000 000 000 000: для UZS это сумы, для USD — центы (125,50 $ = 12550). В интерфейсе и боте доллары вводятся с точностью до двух знаков. Конвертации валют нет. Старые записи сохраняют валюту UZS. Имена и названия курсов обрезаются по краям. Неизвестные поля тела и query отклоняются. Ответы JSON; ошибки всегда `{ "error": "...", "details": null }` либо объект Zod с ошибками полей в `details`. Коды: 201 создание, 200 чтение/изменение, 204 удаление, 400 неверный ввод, 404 отсутствующая запись/маршрут, 409 конфликт курса. Дополнительно 403 для browser-записи с чужого origin. CORS не включён.

Если сервер выбрал другой порт, измените значение `BASE`:

```bash
BASE=http://127.0.0.1:3000

# Создать учебный курс. В новой пустой БД его id будет 1.
curl -i -X POST "$BASE/courses" \
  -H 'Content-Type: application/json' \
  -d '{"name":"English A2","monthlyAmount":850000}'

# Список курсов с числом учеников
curl "$BASE/courses"

# Создать группу, указав её единственный курс
curl -i -X POST "$BASE/groups" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Утренняя","courseId":1}'

# Создать ученика в группе. Ниже для примера используется groupId 1.
curl -i -X POST "$BASE/students" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Азиза Каримова","phone":"+998 90 123 45 67","groupId":1}'

# Ученики одной группы (без groupId возвращаются все)
curl "$BASE/students?groupId=1"

# Изменить одно или несколько полей
curl -i -X PATCH "$BASE/courses/1" \
  -H 'Content-Type: application/json' \
  -d '{"monthlyAmount":900000,"name":"English B1"}'

# Остаток ученика за месяц
curl "$BASE/students/1/balance?month=2026-10"

# Внести оплату (сумма не должна превышать остаток)
curl -i -X POST "$BASE/students/1/payments" \
  -H 'Content-Type: application/json' \
  -d '{"amount":350000,"date":"2026-10-19"}'

# Последние 100 оплат, совместимый ответ-массив
curl "$BASE/students/1/payments"

# История порциями по 10, включая итоги за всё время
curl "$BASE/students/1/payments?limit=10"
# Следующая порция: подставьте nextCursor из предыдущего ответа
curl "$BASE/students/1/payments?limit=10&cursor=КУРСОР_ИЗ_ОТВЕТА"

# Месячный баланс всех учеников: без оплат, с частичной/полной оплатой
curl "$BASE/balances?month=2026-10"

# Должники за выбранный месяц
curl "$BASE/debtors?month=2026-10"

# Текущий месяц
curl "$BASE/debtors"

# Проверка ошибки 400
curl -i "$BASE/debtors?month=2026-13"

# Удалить ученика вместе со всеми его оплатами
curl -i -X DELETE "$BASE/students/1"
```

Поля ученика в API: `id, name, phone, groupId, courseId, group, monthlyAmount, currency, createdAt`. В SQLite — `group_id`, `course_id`, `group_name`, `monthly_amount`, `created_at`. Поле `group` содержит название группы, `courseId` и `monthlyAmount` определяются её курсом. Платёж: `id, studentId, amount, date, createdAt`; `date` соответствует `paid_at` в БД.

С `limit=1…50` история возвращает `{items, total, totalAmount, nextCursor}`. `total` и `totalAmount` относятся ко всем оплатам ученика. `nextCursor: null` означает конец истории. Сортировка — по дате и ID от новых к старым; курсор исключает сдвиг страниц при добавлении новой записи в начало. Некорректный курсор/размер страницы — 400. Без `limit` сохраняется ответ-массив с максимум 100 последними записями; для полной истории используйте страницы. Веб предзагружает первую страницу для первых десяти отфильтрованных учеников (по два запроса одновременно), а также при наведении/фокусе на истории. Кеш живёт до 60 секунд, очищается после изменений оплат и при выходе. Непрогретая история сначала загружается с индикатором на кнопке, затем открывается sheet; при ошибке доступен повтор.

Пример ответа `/debtors` после приведённых операций до удаления:

```json
[
  {
    "studentId": 1,
    "name": "Азиза Каримова",
    "phone": "+998 90 123 45 67",
    "group": "Утренняя",
    "monthlyAmount": 900000,
    "paid": 350000,
    "debt": 550000
  }
]
```

## Веб-интерфейс

Главный экран устроен как wallet в монохромной палитре Vercel: hero, фон, карточки и элементы управления используют общие переменные светлой/тёмной темы. Hero тоже меняет фон и текст при переключении темы; круговое раскрытие из кнопки сохранено. Кнопка выхода временно скрыта. Справа вверху hero — только иконка переключения групп. Popover сразу содержит названия групп с отметкой текущей и кнопку «Создать» внизу; она открывает drawer создания группы после закрытия меню. Помимо обычного нажатия поддерживается удержание 350 мс: ведение пальца подсвечивает строки, отпускание выбирает группу, выход за пределы или отмена касания отменяет выбор. У краёв длинного списка работает автопрокрутка. Доступны клавиатура, Escape и возврат фокуса.

В верхней строке hero дата слева, название группы по центру шрифтом 16px, переключение групп справа. Карандаш стоит рядом с названием: блок занимает ширину текста, ограниченную доступным местом. Верхняя строка закрепляется при прокрутке всей страницы и плавно получает округлённый нижний край; баланс прокручивается вместе с содержимым. Длинное название группы плавно прокручивается. На небольших экранах месяц сокращён, четырёхзначный год сохранён, доступное имя кнопки содержит полную дату. Вкладки находятся вне hero и переключают нижнюю часть. Оплата доступна в карточке и действиях ученика. Соседние месяцы предзагружаются, суммы и счётчики перемещаются и уменьшаются; месяц меняется своей анимацией. Дата находится в левом верхнем углу hero. Поддерживаются свайп и нажатия на края без стрелок. Жест выбора группы не листает месяц. Большая сумма подстраивает шрифт по ширине; измерение не зависит от масштаба соседней карточки и смены темы.

Нажатие на месяц открывает Radix Popover с вертикальными колёсами месяца и года, без видимых заголовков, подписей колонок и крестика. Доступные имена сохранены для скринридера. Popover плавно появляется и закрывается, стрелка рядом с датой поворачивается. Годы 1900–9999 виртуализированы: вместо тысяч DOM-строк отображается только ближайшая область. Работают колесо мыши, touch, стрелки клавиатуры, Page Up/Down, Home/End и Escape. Кнопка «Текущий» плавно прокручивает оба колеса, в том числе при возврате с далёкого года. Выбор применяется кнопкой «Готово»; фокус возвращается к дате.

Для будущих месяцев в вебе показываются `—` и `— / —`, список должников пуст, внесение оплаты из этого представления отключено. Прогнозные начисления не запрашиваются. Список учеников и их тарифы остаются справочником и не зависят от месяца. Серверный контракт `/debtors` и его правила расчёта не менялись; веб намеренно скрывает будущие месячные показатели.

Телефон ученика вводится с защищённым префиксом `+998 (` и маской `+998 (90) 123-56-78`. Поддерживаются вставка полного номера, удаление цифр через разделители и проверка девяти цифр местного номера. Поиск находит телефон и без скобок/пробелов.

Переключатель темы закреплён справа внизу: при прокрутке вниз целиком уезжает за нижний край без затухания, при движении вверх возвращается. На длинной странице слева таким же образом появляется кнопка возврата наверх. CSS-переход transform для этих кнопок отключён, чтобы он не конфликтовал с Framer Motion. Учитываются safe-area и prefers-reduced-motion.

Фильтр справа от заголовка списка открывает Radix Popover с четырьмя вариантами: «Все» (по умолчанию), «Не оплатившие» (`paid = 0`), «В процессе» (`0 < paid < monthlyAmount`), «Оплатившие» (`paid >= monthlyAmount`, включая ранее сохранённую переплату). Фильтр меняет только карточки: hero всегда показывает весь долг и всех должников выбранного месяца. Полностью оплатившие доступны благодаря защищённому `GET /balances?month=YYYY-MM`: формат строки совпадает с `/debtors`, но включены все ученики, а `debt = max(0, monthlyAmount - paid)`. Валидация месяца и текущий месяц по умолчанию одинаковы. Контракт `/debtors` сохранён. Меню поддерживает стрелки, Home/End, Enter и Escape с возвратом фокуса.

Тема раскрывается кругом из центра кнопки с помощью [View Transitions API](https://developer.chrome.com/docs/web-platform/view-transitions/same-document#animating-with-javascript): старый снимок страницы остаётся снаружи, новый появляется внутри растущего круга. Цвета не переключаются по всей странице одновременно. Если API недоступен или включён prefers-reduced-motion, применяется обычное переключение. Один обработчик используется на главном экране и странице входа.

Дата в форме оплаты открывает тот же popover, что в hero, с дополнительным колесом дня. День автоматически ограничивается длиной выбранного месяца (например, 31 января → 28 февраля). MAX заполняет остаток именно за месяц даты платежа. Прогресс показывает результат введённой суммы до сохранения; лишние деньги не принимаются в поле, а сервис повторно проверяет остаток в `BEGIN IMMEDIATE` перед записью. Для нового платежа сверх долга API возвращает 400 с `details.remaining` и ошибкой поля `amount`. Повтор Telegram-квитанции возвращается до проверки остатка, поэтому идемпотентность полной оплаты сохранена. Подзаголовок платежного sheet скрыт визуально, доступное описание сохранено; крестик без фоновой плашки.

По умолчанию язык русский. Переключатель языка временно скрыт на странице входа и в приложении. Переводы RU/UZ и ранее сохранённый выбор остаются в коде.

Название группы в hero ограничено максимальной шириной. Длинная строка плавно уходит влево и появляется справа без разрыва; между полными циклами пауза 3 секунды. При prefers-reduced-motion бегущая строка отключена, полное название доступно через title и скринридер. Карандаш рядом открывает редактирование группы. Пояснение о применении новой стоимости со следующего месяца и сохранении истории находится под «?» рядом с «Оплата в месяц»: открывается нажатием/тапом, наведением мыши или клавишей Enter; Escape и нажатие снаружи закрывают его. Наведение не меняет фокус, курсор можно перевести внутрь подсказки. Hero и карточки в светлой теме используют серый #eaeaea с границей #dedede, отличаясь от фона страницы #fafafa. Заголовок списка оплат и фильтр всегда видны, в том числе в пустой группе и будущем месяце. В пустых вкладках по центру показаны только короткий заголовок и кнопка: создать группу, добавить ученика, очистить поиск, сбросить фильтр или вернуться к текущему месяцу — в зависимости от состояния.

## Учебные курсы

Отдельная вкладка «Курсы» удалена. Создать курс можно круглой кнопкой «+» справа от «Создать группу» внизу drawer. В форме курса слева от «Добавить курс» находится круглая кнопка со стрелкой назад: она возвращает к заполненному черновику группы. После сохранения курса форма группы открывается снова с выбранным новым курсом. Форма курса содержит название, валюту UZS/USD и месячную сумму. Цена USD хранится в целых центах, вводится в долларах. Валюту курса с учениками менять нельзя, как и переводить ученика с оплатами в другую валюту: старые платежи не должны менять свой смысл.

- `POST /courses` — `{name, currency, monthlyAmount}`, `currency` по умолчанию UZS; ответ 201 с `{id, name, currency, monthlyAmount, studentCount, groupCount, createdAt}`. Пример USD: `{"name":"English","currency":"USD","monthlyAmount":12550}` = 125,50 $ в месяц.
- `GET /courses` — все курсы с числом учеников.
- `PATCH /courses/:id` — изменить название/стоимость. Новая цена применяется со следующего месяца по Asia/Tashkent. Текущий и прошлые месяцы сохраняют прежний тариф; суммы и даты записанных оплат не изменяются. Повторные правки заменяют только предстоящий тариф.
- `DELETE /courses/:id` — 204 для неиспользуемого курса, 409 при наличии учеников или групп.
- `POST /students` — `{name, phone, groupId}`, `PATCH /students/:id` поддерживает перевод в другую группу. В вебе у ученика только имя, телефон и выбор группы; варианты подписаны «группа • курс». В запрос передаётся groupId выбранной группы. После сохранения активируется группа ученика. Цена и валюта берутся из закреплённого за ней курса. Длинные подписи в полях, меню и карточках ограничены шириной контейнера и используют такую же плавную прокрутку, как название в hero.

Миграция версии 4 создала courses и course_id. Версия 5 вводит отдельные student_groups и group_id: существующие ученики распределяются по паре старого названия группы и courseId, без изменения их ID, имён, телефонов, цен и оплат. Разные курсы сохраняются в разных группах. Миграция v6 добавляет валюту, оставляя все прежние значения, ID и связи без изменений (UZS), и учитывает валюту в уникальности курса.

## Группы

Каждая группа принадлежит **ровно одному курсу**, выбранному при создании. Курс группы менять нельзя. Все её ученики получают этот курс и его цену; проверка есть в сервисе и SQLite-триггерах. Переименование курса не переименовывает группу. Цена курса обновляет тарифы учеников, но не их принадлежность к группе.

- `GET /groups` — `{id, name, courseId, courseName, monthlyAmount, currency, studentCount, createdAt}[]`.
- `POST /groups` — `{name, courseId}`, ответ 201. Одинаковая пара названия и курса — 409, отсутствующий курс — 404, неверные поля — 400.
- `GET /students?groupId=1`, `/balances?month=2026-10&groupId=1`, `/debtors?month=2026-10&groupId=1` ограничивают данные группой. Без groupId сохранён общий контракт.

Иконка переключения в hero открывает названия групп сразу, без промежуточного drawer. «Создать» внизу popover открывает форму создания группы. Новая группа становится текущей; выбор сохраняется в localStorage. Hero, должники, список учеников и Select оплаты показывают только её учеников. Каталог курсов общий. В форме ученика по умолчанию выбрана текущая группа, при изменении можно выбрать другую группу.

Для совместимости прежние API-варианты `{name, phone, courseId}` и `{name, phone, group, monthlyAmount}` ещё принимаются: они находят/создают отдельную группу соответствующего курса. Они не меняют курс существующей группы. Смешивать groupId с независимыми courseId/ценой запрещено.

`PATCH /groups/:id` принимает `{name?, courseName?, monthlyAmount?}` и атомарно меняет название группы и параметры её курса. Курс группы остаётся фиксированным; правка курса относится ко всем его группам. Доступ — через карандаш возле названия в hero. В веб-форме название курса доступно только для чтения и не отправляется при сохранении группы; можно изменить название группы и месячную стоимость. Круглая кнопка удаления с иконкой находится справа от «Сохранить изменения», требует подтверждения.

`DELETE /groups/:id` удаляет группу, только её учеников, их оплаты и Telegram-квитанции в одной транзакции. Общий курс остаётся, если его используют другие группы; иначе удаляется вместе с версиями тарифа. В drawer удаления открывается маленькое модальное окно с вопросом «Действия необратимы. Вы согласны?» и кнопками «Отмена» / «Удалить всё», начальный фокус на отмене.

## Страница о проекте

Публичная страница `/about` доступна со страницы входа и из меню переключения групп. Она содержит автора Abdulloh Ergashev, описание всех возможностей, правила расчётов, Telegram-команды, таблицу REST API, примеры запросов, стек, запуск с нуля, защиту и ограничения. Справка на русском языке, не запрашивает учеников, платежи или реальные показатели и не раскрывает секреты. Бот: [@corpibotbot](https://t.me/corpibotbot). В меню группы одинаковые название группы и курса показаны один раз; длинные подписи прокручиваются горизонтально без второй видимой строки.

## Telegram

Команды `/debt`, `/students` и пошаговая `/pay` используют выбранную группу; быстрая `/pay <id> <сумма>` работает по явному ID независимо от фильтра. Переход по месяцам и страницам сохраняет группу в callback-кнопке. Будущие месяцы в боте показывают «—», как на сайте. Сообщения и квитанции включают группу, курс и валюту; тарифы берутся за нужный месяц, а не из последней цены каталога.

Все основные сценарии доступны inline-кнопками: главное меню, группы, сводка, должники, карточки учеников, суммы, подтверждение и администраторы. Возврат из карточки сохраняет группу, страницу и месяц исходного списка. Сообщения используют HTML, blockquote, жирные заголовки и code для ID/сумм. У request_users отдельная reply-клавиатура с возвратом и отменой; после завершения она удаляется. USD остаётся доступен для просмотра в боте и оплаты через веб/API, но все пути записи из бота повторно проверяют валюту.

Откройте личный чат с ботом и отправьте `/start`. `/start` и `/help` доступны всем: бот приветствует пользователя, показывает имя, роль и Telegram ID моноширинным текстом `<code>`. Гостю объясняется, как передать ID владельцу; финансовые команды разрешены только владельцу и записям в `admins`. Работа с персональными данными в групповых чатах отключена. Владелец задан в `.env`, не обязан присутствовать в таблице `admins` и не может быть удалён.

- `/start`, `/help` — публичное приветствие, Telegram ID и справка с учётом роли.
- `/about` — публичная справка о проекте, авторе, версии и возможностях.
- `/groups` — группы с курсом, валютой, тарифом текущего месяца и числом учеников; выбор группы либо всех групп, затем сводка и кнопки должников/учеников/оплаты. Выбор личный, хранится в памяти до перезапуска; удалённая группа автоматически сбрасывает выбор на все группы. Создание справочников выполняется на сайте.
- `/debt` — должники выбранной группы за текущий месяц, итог раздельно по валютам без пересчёта, страницы по 4 записи. Кнопки меняют месяц через `editMessageText` в том же сообщении.
- `/pay 12 250000` — быстрая оплата **только UZS**, сразу записывает платёж сегодняшней датой. USD-команды отклоняются без записи; валюта курса не конвертируется.
- `/pay` и «Оплата в сумах» — выбор ученика только из UZS → пресет или ручная сумма → отдельное подтверждение. До подтверждения запись не создаётся. «Назад», «К суммам», «Отмена» и «Главное меню» сохраняют понятный маршрут; возврат/смена суммы обновляет токен, старая кнопка подтверждения недействительна. Ввод истекает через 15 минут.
- `/students` — ученики с ID, страницы по 6 записей.
- `/admins` — только владелец: список, добавление и удаление с подтверждением. Пользователя можно выбрать через `KeyboardButton.request_users`, указать числовой ID или переслать его сообщение. Если Telegram скрывает автора пересылки, нужен числовой ID.

В `/admins` владелец может включить «Админ по следующему /start» или отменить ожидание. По умолчанию режим выключен. Только следующий **новый человек с новым `/start` в личном чате** получает администратора; владелец, действующие админы, боты и групповые чаты не расходуют приглашение. Сообщения с датой до включения не принимаются. Выдача и погашение выполняются атомарно; состояние хранится в SQLite и переживает перезапуск. После первой выдачи режим выключается и сам не включается снова. Новый админ не получает права владельца и не может выдавать доступ другим. Повторное включение — только явная кнопка владельца.

- `/cancel` — завершить ручной ввод. Время жизни сценария — 15 минут; перезапуск отменяет незавершённый ввод.

Права проверяются при каждом update, в том числе на callback-кнопках. Для владельца и каждого администратора задаётся отдельный chat scope `setMyCommands`; меню обновляется при выдаче прав и `/start`. Если администратор ещё не начал чат, Telegram может не принять chat scope до первого `/start` — это не мешает проверке доступа.

Цветные inline-кнопки **поддерживаются**: установлена grammY 1.46.0, в её типах и официальной документации присутствуют `.primary()`, `.success()`, `.danger()` и поле `style`. Проверено по [Telegram Bot API](https://core.telegram.org/bots/api#inlinekeyboardbutton) и [grammY](https://grammy.dev/ref/core/inlinekeyboard). Emoji-fallback не понадобился; внешний вид на старых Telegram-клиентах проверяется вручную.

Повторная доставка одного `/pay` update или повторное применение одного интерактивного intent не создаёт второй платёж: SQLite-таблица `bot_receipts` хранит ключ и платёж в одной транзакции. После удаления ученика квитанции каскадно удаляются. Web POST без такого ключа — отдельная оплата; кнопка блокируется на время сохранения.

Если у токена уже установлен webhook, приложение не снимает его автоматически, чтобы не затронуть другой проект. Бот в таком случае не запускается, API и веб продолжают работать. Один токен должен использоваться только одним polling-процессом.

## Не сделано / допущения

- Ученику, добавленному в середине месяца, начисляется полная месячная сумма; пропорционального расчёта нет.
- Согласно простому контракту `/debtors`, участвуют все существующие ученики, в том числе при выборе прошлого месяца до их создания. История зачисления не ведётся. Тарифы хранятся по месяцам: изменение стоимости применяется с начала следующего месяца и не меняет текущий/прошлые расчёты. Миграция v7 фиксирует исходную цену для прежних записей; утраченные до этой миграции версии цен восстановить невозможно. История переходов между группами не ведётся: при переводе ученика прежние оплаты учитываются в его текущей группе.
- Каждый месяц рассчитывается отдельно: оплата октября не закрывает июль. Будущие месячные показатели в вебе заменены прочерками. Смена месяца просмотра не меняет дату в форме оплаты: по умолчанию она сегодняшняя, месяц платежа определяется явно выбранной датой.
- Новые переплаты запрещены общим сервисом в вебе, API и боте. Ранее сохранённая переплата или переплата после снижения тарифа исключает ученика из должников, но не переносится на следующий месяц. `paid_at`, а не дата создания платежа, определяет месяц. Даты будущих платежей разрешены.
- Текущие месяц и дата одинаковы для веба, API и бота: **Asia/Tashkent (UTC+5)**, независимо от часового пояса компьютера. Поддерживаемые месяцы: 1900-01…9999-11, даты — реальные календарные даты в этом диапазоне. Деньги целые, без округления.
- Вход через страницу `/login` использует `WEB_USERNAME`/`WEB_PASSWORD` из `.env` и серверную cookie-сессию на 12 часов. Полноценные веб-аккаунты, роли и журнал действий ещё не реализованы.
- Нет удаления/редактирования платежей и CRUD учеников в боте: эти функции не требуются ТЗ. Учениками управляет веб/API.
- Telegram-сценарии требуют ручной проверки в клиенте: выбор пользователя, приватные пересылки, отображение стилей кнопок и жест закрытия sheet на настоящем iPhone. Подробности фактической проверки запуска — в `docs/VERIFICATION.md`.
- По явному требованию отключён pinch-to-zoom через viewport, touch-action и обработчики жестов. Фактическое поведение на физическом iPhone требует ручной проверки; axe фиксирует ожидаемое нарушение `meta-viewport` из-за запрета масштабирования.
- Исходники опубликованы в приватном GitHub-репозитории; секреты и рабочая база в него не включены. Отправка задания в Telegram за пользователя не выполнялась.

## Cloudflare Tunnel для демонстрации

После запуска production на 3107:

```bash
cloudflared --config /dev/null tunnel --url http://127.0.0.1:3107 --metrics 127.0.0.1:0 --no-autoupdate
```

Точный HTTPS-адрес `trycloudflare.com` появляется в логе cloudflared. Это временный tunnel к локальному Node.js/SQLite-приложению, а не перенос базы в Cloudflare Workers. Отдельный tunnel и случайный локальный metrics-порт не затрагивают другие проекты. Для внешнего доступа задайте `WEB_USERNAME` и случайный `WEB_PASSWORD` длиной минимум 6 символов в `.env`. Введите их на странице `/login`. Сессия хранится в HttpOnly cookie с SameSite=Strict и Secure при HTTPS; в SQLite хранится только хеш случайного токена. HTML/CSS/JS страницы входа публичны, а `/students`, `/groups`, `/courses`, `/debtors` и `/balances` требуют сессию. Выход через POST /auth/logout отзывает сессию; его кнопка временно скрыта. При смене пароля старые сессии становятся недействительными. Подбор пароля ограничен восемью неудачными попытками за 15 минут с одного адреса. Пустой `WEB_PASSWORD` отключает защиту для локальной разработки. Остановка tunnel закрывает внешний доступ.

## Вход и сессия

- `GET /login` — полноценная страница входа, без системного окна браузера.
- `GET /auth/session` — `{authenticationRequired, username}`; `username: null` без действующей сессии.
- `POST /auth/login` — JSON `{username, password}`; при успехе устанавливает HttpOnly cookie, при неверных данных — 401, при превышении лимита — 429.
- `POST /auth/logout` — 204, удаляет cookie и отзывает токен в БД.

Сессии переживают перезапуск приложения, истекают через 12 часов и не хранят токены в localStorage. При завершении сессии интерфейс возвращает пользователя к форме входа. Миграция БД версии 2 добавляет `web_sessions`, версия 3 — `login_attempts`, версия 4 — справочник курсов, версия 5 — отдельные группы и их привязку с сохранением существующих оплат. Обновление формата хеша учётных данных в этой версии потребует повторного входа один раз. Без `WEB_PASSWORD` локальный режим работает без входа; публиковать такой режим через tunnel нельзя.

При временной сетевой ошибке или HTTP 502/503/504/530 клиент повторяет только GET: максимум три попытки с паузами 350 и 900 мс. Отмена страницы/запроса отменяет повтор. POST/PATCH/DELETE автоматически не повторяются: это исключает автоматическое дублирование оплаты при потере ответа. Ошибка 530 показана понятным сообщением о временной потере связи с Cloudflare.

## Защита и её проверка

Ошибки 401/403/413/429 имеют тот же JSON-формат. Неверные пароли ограничены 8 попытками с IP и 30 суммарно за 15 минут; состояние сохраняется в SQLite после перезапуска. Ответ 429 содержит `Retry-After`. Дополнительно действуют минутные лимиты: 240 запросов с IP, 60 записей с IP, 60 запросов к форме входа суммарно и 1200 запросов ко всему процессу. За Cloudflare учитывается `CF-Connecting-IP` только от loopback-соединения; `X-Forwarded-For` не используется. Это предполагает доверие локальной машине и её connector-процессу.

Размер тела ограничен 16 KiB, ожидание запроса/неактивного соединения — 15 секунд, заголовков — 10 секунд, keep-alive — 5 секунд. Настроены CSP, запрет framing, SameSite/HttpOnly/Secure cookies и проверка Origin/Fetch Metadata для записей. Все SQL-параметры передаются отдельно от запросов.

Выполненные проверки, найденные слабые места и ограничения защиты описаны в [docs/SECURITY.md](docs/SECURITY.md). Это ограниченная локальная проверка; защита от распределённого объёмного DDoS требует настройки внешнего proxy/WAF и наблюдения за нагрузкой.
