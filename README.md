## Что добавлено

- Фактическая дата начала группы и дата зачисления ученика. До первого учебного месяца долг не начисляется.
- Отдельные дата получения денег и период зачёта. Предоплата за один или несколько месяцев, MAX и проверка остатка каждого периода.
- Персональные аккаунты: учитель, администратор, владелец. Назначения групп учителям и общий контроль прав в вебе, API и боте.
- Временный пароль с обязательной сменой при первом веб-входе, привязка Telegram ID, отключение доступа и отзыв сессий.
- Журнал действий владельца, управление сотрудниками и профиль с выходом и сменой пароля.
- Миграция v8 → v10 с сохранением прежних сумм и ID. Неизвестные даты старых записей не подменяются сегодняшней датой.

Сохранены курсы, группы, UZS/USD, месячная история тарифов, RU/UZ, мобильный wallet-интерфейс, фильтры, предзагрузка истории и кнопочный Telegram-интерфейс. Бот принимает оплату только в UZS.

## Запуск отдельной версии

Нужен Node.js 20.19+ и npm. Один `package.json`: Fastify + Zod + SQLite/better-sqlite3, grammY, React/Vite, Radix UI и Framer Motion. API и бот используют общий `LedgerService`.

```bash
git clone --branch next/v2 https://github.com/abdulloh5007/classroom-ledger.git classroom-ledger-v2
cd classroom-ledger-v2
npm ci
cp .env.example .env
```

В `.env` задайте отдельный `WEB_PASSWORD` для владельца preview. `WEB_USERNAME` по умолчанию `preview-owner`. Для новых сотрудников пароль должен быть не короче восьми символов; bootstrap-пароль владельца сохраняет совместимость с минимумом в шесть символов. Для демонстрации используйте отдельные реквизиты, не пароль работающего приложения.

Оставьте `APP_STAGE=preview`, `BOT_TOKEN=` и `OWNER_ID=`. Выбран порт `3108` и отдельный файл `data/preview.db`. Preview отклоняет непустой токен бота, путь вне своего `data` и имя БД, не начинающееся с `preview`. Настройки читаются только из локального `.env`, а не из переменных окружения контейнера или shell.

```bash
npm run seed:preview
npm run dev
```

`seed:preview` работает только на пустом preview-каталоге курсов. Он создаёт вымышленные группы и учеников, UZS/USD, частичные оплаты, предоплату и группу, которая начнёт занятия в следующем месяце. Логины `demo-teacher` и `demo-admin` получают случайные временные пароли: скрипт показывает их один раз. Учителю назначены только две демонстрационные группы. Для демонстрации бота используются тесты с mock Telegram transport; long polling в preview отключён.

Откройте адрес, напечатанный сервером. Если порт занят, приложение выбирает свободный из `PORT…PORT+50`, не завершая чужие процессы. `npm run dev` поднимает API и Vite вместе. Cookie называется `ledger_v2_session`, поэтому не пересекается с сессией 1.3.

Собрать и запустить эту же отдельную preview-копию без Vite:

```bash
npm run build
npm start
```

Предварительно остановите её dev-процесс через Ctrl+C. Сборка в `dist` сама по себе не публикует приложение. Не запускайте эти команды в каталоге работающей версии.

## Правила обучения и оплаты

`createdAt` — техническое время создания записи. `startsOn` — фактическое начало группы; `enrolledOn` — дата зачисления ученика. Первый допустимый учебный месяц определяется более поздней из двух дат. За неполный первый месяц начисляется полная стоимость, как и в исходном допущении ТЗ.

`date` в платеже — фактическая дата получения денег. `billingMonth` или `allocations` задают учебные периоды. Деньги можно получить до начала занятий, если они зачтены за допустимый будущий месяц. При предоплате за несколько месяцев форма распределяет сумму по порядку, начиная с самого раннего незакрытого периода.

Изменение цены курса действует со следующего месяца. Расчёт будущего периода использует известный на момент расчёта месячный тариф; цена будущего месяца не фиксируется отдельным договором при предоплате. Валюты не складываются и не конвертируются: UZS хранятся целыми сумами, USD — целыми центами. Переплата проверяется в транзакции отдельно по каждому месяцу.

В будущем месяце hero показывает полученную **предоплату**, а не просроченный долг. В прошлом/текущем — остаток и число должников. В счётчик входят ученики, обучавшиеся в выбранном месяце.

У старых записей после миграции даты обучения остаются `null`. Редактирование имени не меняет их автоматически: фактическую дату нужно отдельно подтвердить в форме. Пока она неизвестна, сохраняется прежний расчёт без исторического отсечения. При попытке поставить дату, противоречащую существующим оплатам или зачислениям, сервер возвращает 409.

## Права сотрудников

| Действие                                                  | Учитель                 | Администратор | Владелец |
| --------------------------------------------------------- | ----------------------- | ------------- | -------- |
| Группы и ученики                                          | Только свои/назначенные | Все           | Все      |
| Создавать, изменять и удалять доступные группы и учеников | Да                      | Да            | Да       |
| Вносить оплаты и читать историю доступных учеников        | Да                      | Да            | Да       |
| Создавать курсы, менять цены                              | Нет                     | Да            | Да       |
| Выдавать роли, логины, временные пароли и Telegram-доступ | Нет                     | Нет           | Да       |
| Назначать группы учителям и отключать сотрудников         | Нет                     | Нет           | Да       |
| Смотреть журнал действий                                  | Нет                     | Нет           | Да       |

Созданная учителем группа автоматически назначается ему. Проверки выполняются в сервисном слое при каждом чтении и изменении; подмена ID или старые кнопки бота не открывают чужие данные. Роль владельца одна; её нельзя выдать через API сотрудников, отключить или заменить обычным редактированием.

Владелец открывает «Сотрудники и роли» в меню групп. Там же доступны журнал, назначения групп, смена Telegram ID и выдача нового временного пароля. Пользователь сначала меняет временный пароль, затем получает доступ к финансовому API. Telegram-доступ привязывается владельцем отдельно и не требует входа в веб. Смена роли, групп, пароля или активности отзывает веб-сессии; бот проверяет актуальную роль и группы на каждом действии.

Пароли сотрудников хранятся только как scrypt-хеши с индивидуальной солью. Bootstrap-пара владельца из `.env` применяется при первом старте; пока владелец сам не сменил пароль через профиль, изменение bootstrap-реквизитов также меняет его доступ. После самостоятельной смены пароля `.env` больше не перезаписывает этот пароль при старте.

## API

Все финансовые и административные маршруты требуют cookie-сессию. После входа через `POST /auth/login` сохраните cookie; примеры ниже предполагают файл `cookies.txt` с сессией своего preview. Новые аккаунты до смены временного пароля получают 403 для финансовых маршрутов.

| Маршрут                                                      | Назначение                                                |
| ------------------------------------------------------------ | --------------------------------------------------------- |
| `POST /auth/login`, `GET /auth/session`, `POST /auth/logout` | Вход, состояние сессии, выход                             |
| `GET /auth/profile`, `POST /auth/password`                   | Свой профиль и смена пароля                               |
| `GET /staff`, `POST /staff`, `PATCH /staff/:id`              | Сотрудники, только владелец                               |
| `GET /audit?before=ID`                                       | Журнал, до 50 записей; только владелец                    |
| `GET/POST /courses`, `PATCH/DELETE /courses/:id`             | Каталог курсов; изменения только администратору/владельцу |
| `GET/POST /groups`, `PATCH/DELETE /groups/:id`               | Доступные группы                                          |
| `GET/POST /students`, `PATCH/DELETE /students/:id`           | Доступные ученики                                         |
| `GET/POST /students/:id/payments`                            | История/внесение оплаты                                   |
| `GET /students/:id/balance?month=YYYY-MM`                    | Остаток за учебный период                                 |
| `GET /balances`, `GET /debtors`                              | Балансы/должники с параметрами `month`, `groupId`         |

Примеры для пустой базы после создания первого курса:

```bash
BASE=http://127.0.0.1:3108

curl -b cookies.txt -X POST "$BASE/groups" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Утренняя","courseId":1,"startsOn":"2026-10-15"}'

curl -b cookies.txt -X POST "$BASE/students" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Азиза","phone":"+998901234567","groupId":1,"enrolledOn":"2026-10-15"}'

# Получили в октябре, зачли за ноябрь.
curl -b cookies.txt -X POST "$BASE/students/1/payments" \
  -H 'Content-Type: application/json' \
  -d '{"amount":100000,"date":"2026-10-21","billingMonth":"2026-11"}'

# Одно поступление за два периода. Распределение должно совпасть с amount.
curl -b cookies.txt -X POST "$BASE/students/1/payments" \
  -H 'Content-Type: application/json' \
  -d '{"amount":200000,"date":"2026-10-21","allocations":[{"month":"2026-11","amount":100000},{"month":"2026-12","amount":100000}]}'

curl -b cookies.txt "$BASE/students/1/payments?limit=10"
curl -b cookies.txt "$BASE/debtors?month=2026-11"
```

Нельзя передавать одновременно `billingMonth` и `allocations`. В одном распределении не более 24 уникальных месяцев; веб-форма предлагает до 12. Если период не указан, для совместимости используется месяц `date`. История возвращает исходное поступление и массив распределений. Создание — 201, удаление — 204, валидация/переплата — 400, отсутствие доступа — 401/403, недоступные чужие объекты — 404, конфликт исторических дат — 409. Ошибки имеют форму `{error, details}`.

Старый формат ученика со свободным названием группы и суммой сохранён только для совместимого импорта администратором/владельцем и внутренними инструментами. Он создаёт записи без подтверждённой даты; обычный интерфейс использует `groupId` и даты. Учитель не может через этот формат создать курс или обойти запрет изменения тарифа.

## Telegram

Поддерживаются `/start`, `/help`, `/groups`, `/students`, `/debt`, `/pay`, `/admins`, `/cancel`. В платеже кнопками можно выбрать предыдущий/следующий учебный месяц, сумму и подтверждение. В сообщении указаны дата получения и месяц зачёта. Переход периода меняет токен намерения; старое подтверждение не создаёт платёж.

Быстрая `/pay ID сумма` сохраняет оплату за текущий месяц; для предоплаты используйте кнопки. Бот принимает только сумы. Владелец и старые Telegram-администраторы сохраняют доступ при переносе. Новые сотрудники используют назначенную в вебе роль и Telegram ID. Одноразовая выдача администратора через `/start` остаётся явным действием владельца, по умолчанию выключена.

Рабочий бот в этой preview-версии не запущен. Тесты используют подставной Telegram transport; перед будущим выпуском нужен ручной проход в отдельном тестовом боте, а затем согласованный переход рабочего токена на один новый polling-процесс.

## Ограничения и статус

- Это beta для отдельной демонстрации, не установленное обновление production.
- Перевод ученика с оплатами пока запрещён: полноценная история переводов ещё не реализована. Изменение группы не должно переписывать прежние финансовые отчёты.
- Нет возвратов, редактирования/отмены платежей и переноса избыточного остатка после смены будущего тарифа.
- Переключатель языка остаётся скрытым; новые административные экраны пока на русском. Предыдущие переводы RU/UZ сохранены.
- По прежнему требованию отключён pinch-to-zoom; это сохраняет известное исключение axe `meta-viewport`.
- Пустой `WEB_PASSWORD` оставляет локальный режим без авторизации; для демонстрации ролей задайте его перед запуском.
- Постоянный хостинг, физический iPhone и реальный тестовый Telegram-клиент не заявляются проверенными без отдельного прохода.
